# 배포 후 실제 계정 테스트 가이드

지금까지의 unit/component/E2E 테스트는 전부 GIS(Google Identity Services)와
Drive/Sheets API를 mock한 것이다. 실제 Google 계정으로 로그인해 진짜 Drive
폴더와 Sheet를 불러오는 흐름은 한 번도 검증된 적이 없으므로, 배포 후 아래
순서로 직접 확인한다.

## 0. 준비물

- Google 계정 1개(테스트용으로 새로 만들어도 됨).
- 문제은행 역할을 할 Google Sheet 1개 이상, 그 Sheet가 들어있는 Drive
  폴더(=`README.md`가 말하는 "자격증 폴더"의 상위 폴더).
- Sheet 헤더 형식은 `docs/superpowers/specs/2026-09-03-sheet-quiz-architecture-design.md`
  §7~8(헤더 별칭, 필수/선택 컬럼)을 참고. 최소 한 시트는 정상 데이터로,
  최소 한 시트는 일부러 헤더 오류/정답 개수 불일치 등을 넣어 검증 화면도
  테스트한다.

## 1. Google OAuth 클라이언트 발급 (`README.md` "사전 준비" 절 그대로)

1. Google Cloud Console에서 프로젝트 생성.
2. OAuth 2.0 클라이언트 ID(웹 애플리케이션) 발급.
3. "승인된 자바스크립트 원본"에 **로컬 주소(`http://localhost:5173`)** 를
   먼저 등록 — 로컬에서 먼저 검증하고 나중에 배포 도메인을 추가하는 순서를
   권장한다.
4. Drive API, Sheets API 사용 설정.

## 2. 로컬에서 먼저 검증 (배포 전에 여기서 문제를 걸러낸다)

```bash
cp .env.example .env.local   # 이미 있다면 생략
# .env.local에 VITE_GOOGLE_CLIENT_ID 채우기
pnpm dev
```

`http://localhost:5173`에서 아래 골든 패스를 실제 계정으로 한 번 완주한다.

1. 시작 화면 → "Google Drive 연결" → 실제 Google 로그인 동의 화면이 뜨는지.
2. 최상위 폴더 선택(`/folders/select`) → 실제 Drive 폴더 트리가 보이는지.
3. 자격증 폴더 진입(`/folders/:folderId`) → 하위 폴더/Sheet 파일 목록이
   실제 내용과 일치하는지.
4. Sheet 선택 → 탭이 여러 개면 탭 선택 화면(`/sheets/:id/tabs`), 하나면
   자동 선택되는지.
5. 검증 화면(`/sheets/:id/validate`) → 정상 시트는 "검증 완료"로, 오류를
   넣은 시트는 실제 오류 목록(행/필드/사유)이 정확히 뜨는지. 오류 목록
   복사/Markdown 다운로드 버튼도 눌러본다.
6. "풀이 시작" → 문제풀이 화면(`/quiz/:attemptId`) → 단일/복수 정답 선택,
   보류 표시, 다시보기 표시, 문제 네비게이터 상태 변화, 자동저장 표시
   (`저장 중…` → `저장됨`)가 실제로 도는지.
7. 브라우저 새로고침 → 같은 문제, 같은 진행 상태로 돌아오는지(이어풀기).
8. 제출 확인(`/quiz/:attemptId/submit`) → 제출 → 결과 화면
   (`/results/:attemptId`) → 점수/정오표/선택지별 해설이 Sheet 원본과
   맞는지.
9. 결과 화면에서 Markdown/JSON 내보내기 다운로드.
10. 기록 화면(`/history`)에 방금 푼 기록이 보이는지, "결과 보기"로
    들어가지는지.
11. 설정 화면(`/settings`)에서 최상위 폴더 재설정, 전체 데이터 삭제를
    각각 한 번씩 실행해 정상 동작(재설정 후 폴더 선택 화면으로 이동,
    전체 삭제 후 로그아웃되고 시작 화면으로 이동)하는지.
12. 다크모드 토글 확인(헤더 우측 버튼).
13. 브라우저 창을 좁혀 모바일 폭에서 네비게이터 접기, 하단 버튼 줄바꿈이
    깨지지 않는지 확인.

## 3. 배포

`README.md` "배포" 절 참고. Vercel 기준 요약:

1. GitHub 저장소를 Vercel에 import.
2. 환경변수 `VITE_GOOGLE_CLIENT_ID` 등록.
3. 배포 완료 후 나온 도메인을 OAuth 클라이언트의 "승인된 자바스크립트
   원본"에 **추가**(로컬 주소는 지우지 않아도 됨).
4. 재배포 없이 바로 새 도메인에서 로그인이 되는지 확인(OAuth 클라이언트
   설정은 즉시 반영됨).

## 4. 배포된 사이트에서 한 번 더

2번의 골든 패스(1~13)를 배포된 실제 도메인에서 한 번 더 반복한다. 로컬과
다르게 나타날 수 있는 부분 위주로 특히 확인한다.

- 자산 로드 실패(404)나 콘솔 에러가 있는지 개발자 도구로 확인.
- 로그인 리다이렉트/팝업이 배포 도메인에서도 정상 동작하는지(원본 등록
  누락 시 `redirect_uri_mismatch` 또는 `origin mismatch` 에러가 남).
- HTTPS 환경에서 다크모드/새로고침 이어풀기가 로컬과 동일하게 동작하는지.

## 5. 의도적으로 깨뜨려서 확인 (에러 처리 회귀 테스트)

Phase 6 리뷰에서 고친 항목들이 실제 환경에서도 맞물리는지 확인한다.

- 문제풀이 중 답변을 하나 고르고 저장 표시가 뜨기 전에 바로 브라우저 탭을
  닫거나 뒤로가기 → 다시 열었을 때 방금 답변이 저장돼 있는지(자동저장
  flush).
- 한 문제 세트를 제출까지 끝낸 뒤, 같은 Sheet에서 다시 "풀이 시작"을 눌러
  결과로 안내되는지, 기록 화면에서 "처음부터 다시 풀기"가 정상 동작하는지.
- 기록 화면(`/history`)이나 설정 화면에서 삭제 도중 네트워크를 강제로
  끊어보고(개발자 도구 Network 탭 → Offline), 에러 배너가 뜨고 계정 연결이
  유지된 채 재시도 버튼이 살아있는지.
- Drive 폴더 목록을 불러오는 도중 다른 폴더를 빠르게 연달아 클릭해도
  화면이 엉키지 않는지(stale request 가드).

## 6. 알려진 제약 (버그 아님, README에도 명시)

- 여러 탭에서 동시에 같은 풀이를 열면 마지막 저장만 남는다.
- 오프라인 상태에서는 Drive/Sheet 최초 조회가 불가하다(이미 불러온 풀이는
  이어서 가능).
- GitHub Pages로 배포할 경우 `vite.config.ts`에 `base` 경로를 직접
  추가해야 한다(README "배포" 절 참고) — Vercel/Cloudflare Pages는 해당
  없음.
- 최근 사용 목록, 결과 화면 분류·난이도 필터, Drive 1,000개 초과 시
  페이지네이션은 이번 범위에서 구현하지 않았다(Phase 6 리뷰에서 minor로
  기록, 의도적 보류 — 필요해지면 별도 작업으로 추가).

## 문제가 생기면

- `origin mismatch` / `redirect_uri_mismatch`: OAuth 클라이언트의 "승인된
  자바스크립트 원본"에 지금 접속 중인 도메인(포트 포함)이 정확히
  등록됐는지 확인.
- 로그인은 되는데 폴더 목록이 안 뜸: Drive API가 사용 설정됐는지, 로그인한
  계정에 실제로 접근 가능한 폴더/파일이 있는지 확인.
- Sheet를 읽어오지 못함: Sheets API 사용 설정 여부, 스프레드시트 ID가
  올바른지 확인.
- 그 외 재현되는 문제는 어떤 화면에서, 어떤 조작으로, 어떤 증상이
  나타났는지 알려주면 원인을 좁혀서 다음 작업으로 정리한다.
